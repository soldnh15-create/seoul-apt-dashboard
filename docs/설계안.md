# 설계안과 단계별 계획

## 1. 전체 흐름

```text
[GitHub Actions · 매일 04:30 KST]
  수집 collect ── 공공데이터포털 매매·전월세 API (최근 3개월 재수집 + 과거 이어받기)
     │              └ data/raw/{trade|rent}/{시군구}/{연도}.csv.gz  (커밋)
  선택 kapt·geo·macro ── 키가 있을 때만 (data/kapt, data/geo, data/macro)
  지표 build ── 단지 식별 → 지표 → site/data/*.json (지역·단지별로 쪼갬)
  검증 validate ── 실패하면 여기서 멈춤(배포 안 함)
  배포 ── GitHub Pages (site/ 폴더 통째로)
  알림 notify ── 텔레그램(설정이 있을 때만)
```

## 2. 설계 결정과 이유

| 결정 | 이유 |
|---|---|
| Python 표준 라이브러리 위주(외부 패키지는 PyYAML·pytest뿐) | 설치·유지 부담을 줄이고, 포크한 사람이 바로 돌릴 수 있게 |
| 사이트는 빌드 도구 없는 HTML·JS | Node 설치 없이 수정·배포. Actions 시간을 아낌 |
| 원천 데이터는 시군구·연도별 gzip CSV, 달 단위로 통째 교체 | 멱등(여러 번 돌려도 같음), 파일 하나 50MB 미만, git 변경이 최근 연도 파일에만 생김 |
| 구 단위로 차례차례 계산 | 전국으로 늘려도 메모리가 구 하나 크기만 필요 |
| 사이트 데이터는 `meta` / `sido` / `gu` / `apt` / `index` 로 분리 | 첫 화면은 시도 요약만 받고, 단지 파일은 그 단지를 열 때만 받음 |
| 단지 ID = 매매의 단지 일련번호(aptSeq) | 이름이 바뀌어도 유지됨. 전월세는 동·지번·이름으로 붙이고, 못 붙인 것은 목록으로 남김 |
| 가상 샘플은 `data/sample/` 에만, 화면에 경고, 배포 검증에서 차단 | 지어낸 숫자가 실제처럼 공개되는 사고 방지 |
| 선택 기능은 키가 없으면 건너뜀 | 필수 키 1개만으로 사이트가 완성되게 |

## 3. 사이트 데이터 모양

- `meta.json` — 갱신 시각, 기준일, 브랜드, 시도·구 목록, 면적 구간, 켜진 기능
- `sido/{코드}.json` — 핵심 지표, 월별·주간 시계열, 구별 순위, 신고가·저가 직거래 목록, 연식별
- `gu/{시군구}.json` — 구 지표, 시계열, 동별 비교·시계열, 신고가
- `apt/{시군구}/{단지ID}.json` — 면적별 지표, 거래 전체(`[계약일, 면적, 층, 금액, 표시]`), 전월세 전체, 스펙·좌표
- `index.json` — 전 단지 한 줄 요약(검색·조건 검색·점수·지도·순위가 함께 씀)
- `report/{코드}.json` — 주간 요약(규칙 기반 문장 + 숫자 검증을 통과한 AI 글)

## 4. 단계별 계획과 진행

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 수집 → 정제 → 지표 + 테스트 | 완료 |
| 2 | 25개 구 백필(체크포인트·한도 관리) + 일일 워크플로 + 검증 | 완료(워크플로는 GitHub에 올린 뒤 실제 실행 확인 필요) |
| 3 | 사이트 MVP(홈·구·단지 상세·검색) + Pages 자동 배포 | 완료(배포는 미실행) |
| 4 | 비교·지도·조건 검색·점수·개인화 | 완료 |
| 5 | K-apt·카카오 입지, 금리·지수, AI 리포트, 텔레그램, PWA | 코드 완료 · **실제 키로 미검증** |
| 6 | 추가 기능 | 단지 순위(4가지 기준), 필요 자금 계산기, 연식별·주간 거래량, 공유용 이미지 |

## 5. 미확인·미검증 (실제 키를 넣은 뒤 확인할 것)

1. 매매·전월세 실제 응답으로 파서 대조(문서의 항목 이름으로만 작성함).
2. 전월세 응답에 단지 일련번호가 오는지. 안 오면 동·지번·이름 매칭률을 `data/state/unmatched_rent.csv` 로 확인.
3. K-apt 응답의 JSON 모양(`AptListService4`, `AptBasisInfoServiceV5` — 2026-08에 버전이 올라감).
4. ECOS 통계코드(기준금리 722Y001, 주담대 121Y006 — 기억 기준), R-ONE 통계표 ID(비어 있음), Gemini 무료 모델명.
5. 카카오 로컬 API 하루 한도.
6. GitHub Actions 한 번 실행에 걸리는 시간(백필 첫날).

## 6. 더 커질 때

- 저장소가 1GB에 가까워지면: 2년보다 오래된 연도 파일을 GitHub Releases 자산으로 옮기고, `collect` 앞에 "내려받기" 단계를 둔다. 최근 2년만 저장소에 남긴다.
- 전국 확장: `regions.yaml` 에 시도 추가. 하루 한도(10,000건) 때문에 백필이 며칠 걸리며 자동으로 이어받는다. 운영계정으로 바꾸면 한도를 늘릴 수 있다.
